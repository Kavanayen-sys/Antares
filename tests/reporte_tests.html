1. Fundamento Teórico y Definición

Los test unitarios (pruebas unitarias) son procedimientos de comprobación automatizados que se ejecutan sobre una porción aislada y específica de código (generalmente funciones, métodos o clases individuales), con el propósito de garantizar que dicha unidad cumpla rigurosamente con su comportamiento esperado bajo diversas condiciones de entrada.

A diferencia de las pruebas de integración (que verifican la interacción entre subsistemas y bases de datos) o las pruebas funcionales de extremo a extremo, los test unitarios aíslan la lógica pura de negocio. Si una prueba unitaria falla, la causa raíz es inmediata e inequívoca.

Ejemplo práctico en PHP aplicado al proyecto:
// Función o método bajo prueba (Unidad): function validarCapacidadContenedor(float $capacidad): bool { if ($capacidad <= 0) { throw new InvalidArgumentException("La capacidad debe ser mayor a cero."); } return true; } // Test Unitario de verificación: $resultado = validarCapacidadContenedor(3200); if ($resultado === true) { echo "Test aprobado: capacidad válida aceptada."; }

2. Objetivos y Utilidad en SiGeRU

  1. Detección temprana de anomalías: Permite atrapar bugs de validación antes de que lleguen a producción o impacten la base de datos MySQL.
  2. Verificación de reglas de negocio críticas: Asegura que reglas como el mínimo de 50 contenedores por ruta, la incompatibilidad de roles de chofer/peón idénticos y la protección de flotas activas se respeten siempre.
  3. Prevención de regresiones: Brinda confianza al equipo de desarrollo de que modificaciones en el código no romperán características que ya funcionaban.
  4. Mantenimiento y refactorización ágil: Actúa como una especificación viva y ejecutable de los requerimientos funcionales (RF) y reglas de negocio (RN).
